# results/checks — reference data of the reproducibility checks

What the checks of [`../../checks/`](../../checks/README.md) compare against when a live recomputation is not
possible here (no GPU, no mpmath) or would depend on a file outside the repository, and the inputs they and
`make -C series` take from the computing campaigns. Data under CC BY 4.0
([`../../LICENSE-DATA.md`](../../LICENSE-DATA.md)); third-party files keep their origin, given below.

| Path | Used by | What it is |
|---|---|---|
| `reference/sample.tsv` | I1 | points of b, h, c classes at 3–7 loops (log-coordinates, exact doubles) with the value of the projective integrand and the sum of the absolute values of the forest terms, evaluated in 100-digit arithmetic by `checks/reference/rebar_mp.py` (mpmath 1.3.0); written by `checks/I1_pointwise.py --make-sample` on 17 October 2026 |
| `golden-cpu/` | N2, `integrator/run_all.sh` | the CPU golden references: `rebar_cpu run --pilot 65536 --samples 0 --seed 2026` (version 0.3.0) for b, h at 3–6 loops, c at 3–5, int4 at 4–5, exactly samples 0–65535 of every class, which a GPU run on the same counters must reproduce to round-off (`integrator/tools/golden_check.py`); `v0.2.0-cuda/` holds the files of the legacy stream scheme ([`golden-cpu/README.md`](golden-cpu/README.md)) |
| `golden-gpu/2026-10-14-h200x4-validation/` | N2 | the golden GPU runs of the campaign of 14 October 2026 (version 0.3.0, 4 × H200, `gpu-node-2`; campaign `2026-10-14-h200x4-validation`): `golden_<kind>_L<L>.json` as written by `rebar_gpu run --backend cuda ... --pilot 65536 --samples 0 --seed 2026`, with the command line of each (`.cmd`): b 3–6, h 3–6, c 3–5, int4 4–5, b 5 on each GPU alone (`_dev0`–`_dev3`), b 5 and int4 5 with forced splits (`_split32`, `_split8`) |
| `golden-gpu/2026-10-15-h200x8-weekend/` | N2 | the golden runs of the start-up self-test of the weekend campaign (version 0.4.0, 8 × H200, `gpu-node-3`; campaign `2026-10-15-h200x8-weekend`): b 5 with both limit variants, h 5, c 4, and the driver's self-test summary |
| `replicas/sums.tsv`, `replicas/classes.tsv` | N7 | the 48 replicas of campaign `2026-10-18-h200x1-replicas` (18 October 2026, version 0.4.3, e16, one H200 each; eight replicas of each of $B_6$, $H_6$, $C_6$, $B_7$, $H_7$, $C_7$): per replica the order sum and its error, samples, core time, reference, time and node (`sums.tsv`), and per replica and class at $N = 1$ the samples, contribution and its error, kurtosis and largest weight (`classes.tsv`), extracted from the 48 run files |
| `fourloop/fourloop-sums.tsv`, `fourloop/fourloop-classes.tsv` | N8 | the 18 four-loop runs of campaign `2026-10-14-h200x4-validation` (14 October 2026, version 0.3.0, 4 × H200): the eight replicas of each of $B_4$ and $H_4$ and the validation and production runs of $H_4$; per run its id, role, seed, order sum and error, samples, core time, reference, time and node (`fourloop-sums.tsv`), and per run and class at $N = 1$ the samples, contribution and its error, kurtosis, largest weight and round-off scales (`fourloop-classes.tsv`), extracted from the 18 run files |
| `routeb/runs/` | S4, `make -C series` | route B at eight and nine vertices, campaign `2026-10-18-h200x1-routeb` (18 October 2026, version 0.4.3, e16 and e18, one H200 per run): the six run JSONs (int4 at 7 and 8 loops, int2 and int2d at 8 and 9), xz-compressed, as `series/routeb.py` reads them |
| `routeb10/runs/` | S4, `make -C series` | route B at ten vertices, campaign `2026-10-19-h200x1-routeb10` (19 October 2026, version 0.4.3, e18 and e20, 32 shards on one H200 each): int4 at 9 loops, int2 and int2d at 10, each the sum of its shards (per class only the Nickel index, samples, weight polynomial, value and error), xz-compressed |
| `phi4tools/int4pt0{2..6}.txt`, `int2pt0{2..5}.txt`, `int2pt08.txt` | G3 | Phi4tools' graph lists (G. Sberveglieri, G. Spada, JHEP 05 (2024) 073; github.com/g-spada/Phi4tools, tag v1.0.2 = commit `abd3b8b85ff66e0fb51dfb1e72f773ccfc33b43b`, `paclet/Resources/INTEGRANDS/`), byte for byte; fetched on 13 and 17 October 2026, SHA-256 in `checks/G3_phi4tools.py` (`G3_phi4tools.py --fetch` downloads them again and compares). The 6–7-loop files are in `integrator/data/lists/`. Phi4tools' MIT licence is in `phi4tools/LICENSE-Phi4tools.txt` |
| `phi4tools/routeb-sums.json` | S4, `make -C series` | route B from Phi4tools: per order the sums over the graphs of $\Gamma^{(4)}$, $\Gamma^{(2)}$ and $\partial_{p^2}\Gamma^{(2)}$ (two to eight quartic vertices) of Phi4tools' per-graph values times their $O(N)$ factors, as polynomials in $N$ with their errors, derived from `Resources/VALUES` and `FACTORS` of Phi4tools v1.0.2 (the SHA-256 of every source file inside), as `series/routeb.py` reads them |
| `gau/beta.specs` | G4 | GAU's four-loop tables (P. Ribeca, 2005; GAU's `beta.specs`, SHA-256 `11a479d71dcbb6a87d52ef8f1a3e75954c809c1502500e3eb79feb9cd603b5f0`): one line per graph, with the weight and $O(N)$ polynomial computed by GAU |

The complete records of these campaigns (reports, logs, environment records) are kept outside the public repository,
and the run files of the ledger's contributions are in its run archive. The copies here are those files without what
would identify the machines or the user: the runs and tables name a node by a label (`gpu-node-N`), and keep no host
name, GPU UUID or PCI bus id, job id or directory of the cluster.
